HR Onboarding on AWS: workflow and data flow

Docker on ECS Fargate (private subnets) with MongoDB Atlas for the student records and S3 for the documents and HR tables (shared bucket igtl-hr-analytics-ayush-2026). Scales with load; containers stopped 12:00 am to 8:00 am IST. Numbered arrows follow one student's submission and the HR review.

What each numbered arrow means

#From → ToWhat happensWhere it is recorded
1Student → ALBThe student opens the onboarding address (HTTPS) and reaches the ALB. Between 12 am and 8 am IST no container is running, so the ALB answers HTTP 503.ALB access logs
2ALB → onboarding taskThe ALB checks the HTTPS certificate and rule, then forwards to one of the onboarding containers on port 8000 (private subnet; the task accepts traffic only from the ALB security group). Any container can serve any student.ALB access logs, CloudWatch Logs
3Onboarding task → Gemini APIUploaded documents (PAN, Aadhaar, resume, certificates) are read and checked, going out through the NAT gateway. The key is injected from SSM Parameter Store at start, never in the image.CloudWatch Logs (errors only, no PAN or Aadhaar in logs)
4Onboarding task → MongoDB AtlasTakes the next student ID from the atomic counter (so two containers never issue the same ID), then saves the application as one document in applications (_id = IGTPL007) and the form in forms. Atlas accepts only the NAT gateway's address.Atlas logs, CloudWatch Logs
5Onboarding task → S3Documents go to the student's own folder onboarding/employees/<id>/documents/ in your documents bucket. employees/ and employee_education/ rows (<id>.parquet, top level, no hr/ prefix) go to the shared bucket. Bank and sensitive rows (account number, IFSC, PAN, Aadhaar, phone) go to hr/<table>/ in your restricted bucket only; the app refuses to start if the restricted or documents bucket is missing or is the shared bucket.CloudTrail S3 data events, S3 access logs (your buckets)
6HR staff → ALB (HR domain)HR opens the HR portal. The ALB rule lets only the office IP range through (other IPs get 403), then HR signs in.ALB access logs, CloudWatch Logs
7ALB → HR taskThe ALB forwards to the HR container on port 8001.CloudWatch Logs
8HR task → MongoDB and S3Reads the records from MongoDB and the documents from S3, so HR always sees the latest data. On approve, reject or flag it updates the MongoDB document and rewrites that student's Parquet rows.CloudTrail S3 data events, Atlas logs
9Analyst → Athena → Glue → shared bucketApproved analysts run SQL. Athena uses the Glue table definitions to read the Parquet files in the shared bucket. The restricted tables are only for the HR-admin role.Athena query history, CloudTrail

Daily timeline (India time)

TimeWhat happens
00:00Application Auto Scaling sets both services to 0 tasks. Fargate stops billing. The ALB, NAT gateway and MongoDB stay on.
00:00 to 08:00The ALB answers HTTP 503 (no healthy container). Records stay in MongoDB and files in S3. Logging keeps recording AWS-side activity.
07:55The schedule starts one task per service (about a minute to start). The app is ready at 08:00.
08:00 to 24:00The CPU rule adds containers when busy (portal up to 4, HR up to 2) and removes them after. Errors and policy changes email you through SNS.
DailyYou glance at the alert email and open both portals once.
