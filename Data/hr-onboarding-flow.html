HR Onboarding · react_onboard.py + hr_info.py

How an onboarding submission travels from the employee to HR

Two small Python web apps that never talk to each other directly. The employee form writes files into the project folder, and the HR portal reads the same files. There is no database.

Employee app, port 8000 Local AI model Data folder on disk HR app, port 8001

Step by step

  1. 1
    The employee uploads Aadhaar and PAN
    The form sends both images to POST /api/extract. Pillow shrinks each one to at most 1024 px, then Ollama runs the local vision model on it. Nothing leaves the machine.
  2. 2
    The form fills itself in
    The model returns JSON. Name and date of birth come from PAN first and Aadhaar as a fallback, the father's name comes from PAN, and the address comes from Aadhaar.
  3. 3
    The employee completes and submits the form
    The rest of the form and all three JPGs go to POST /api/submit. The server checks that required fields are filled, the email and phone are valid, the date is DD/MM/YYYY, the age matches it, and the declaration is ticked.
  4. 4
    Two things are written to disk
    A new ID like EMP-1A2B3C4D is generated. The record goes to submissions/EMP-….json with status Pending HR Review, and the images go to uploads/EMP-…/.
  5. 5
    The HR portal reads the folder
    hr_info.py scans submissions/EMP-*.json on every refresh and serves the JPGs from uploads/. IDs are checked against EMP-[0-9A-F]{8} so no other files can be requested.
  6. 6
    HR reviews the submission
    HR can search, filter by status, open a record, see the documents full size, and download the record as JSON.
  7. 7
    The decision is saved back into the same JSON
    Approve, Reject or Mark as pending updates application_status and adds reviewed_at in that employee's file.

Technology used

In the browser

React 18.3.1Both portals' UIs, loaded as UMD scripts from unpkg
Babel Standalone 7.26Compiles the JSX in the page, so there is no build step
fetch + FormDataSends files and form data to the Python APIs

On the server

Python 3.12Language for both apps
StarletteRoutes, form and file parsing, JSON and file responses
UvicornWeb server; port 8000 for employees, 8001 for HR

Document reading

OllamaRuns the AI model locally; must be running in the background
Vision modelVision model that reads PAN and Aadhaar; JSON mode, temperature 0
PillowResizes and re-encodes images before they go to the model

Storage

JSON filesOne record per employee in submissions/
JPG filesAadhaar, PAN and photo in uploads/<id>/
uuidBuilds the EMP-XXXXXXXX employee ID

Inside a submission file

// submissions/EMP-1A2B3C4D.json (shape only)
{
  "employee_id": "EMP-1A2B3C4D",
  "personal_information": { name, father_name, date_of_birth, age, gender, passport_number, email, emergency_contact, languages, hobbies },
  "address": { permanent_address, current_address },
  "family_details": [ { Name, Age/Gender, Relation, Occupation } ],
  "education_details": [ { Qualification, University/Institute, Year of Passing, % Marks, Major Subject } ],
  "professional_details": { total_experience, last_organization, last_designation, employment_history },
  "references": { senior_1, senior_2 },
  "documents": { aadhaar: "aadhaar.jpg", pan: "pan.jpg", photo: "photo.jpg" },
  "application_status": "Pending HR Review",   // changed by hr_info.py
  "submitted_at": "2026-11-02T10:15:00",
  "reviewed_at": "…"                          // added by hr_info.py
}

Because the folder is the only link between the two apps, both must run from the same project folder. Deleting a JSON file removes that employee from the HR portal, but their images stay in uploads/.
